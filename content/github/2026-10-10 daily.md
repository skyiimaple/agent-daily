# 2026-10-10 GitHub 日报

今日精选 5 个值得动手学的开源项目（偏 Agent / 工程实践）。

## 1. google/adk-python — Google Agent Development Kit

**介绍**  
Google 开源的 code-first Python Agent 工具包：用普通软件工程方式定义 agent、工具与编排，支持多智能体层次、MCP/OpenAPI、评估与部署。模型无关，可对接 Gemini 以外的运行时。

**用法**  
仓库与文档：[github.com/google/adk-python](https://github.com/google/adk-python) · [ADK Docs](https://google.github.io/adk-docs/)。用 Python 定义 agent 与 tools，再按文档部署到 Cloud Run / Vertex Agent Engine；也可先在本地跑通编排再容器化。

**应用场景**  
企业级多智能体工作流、需要可测试/可版本化 agent 逻辑、要把现有 OpenAPI/MCP 工具接到 agent 的团队。

**推荐学习程度**：进阶

---

## 2. vercel/eve — 文件系统优先的持久 Agent 框架

**介绍**  
Vercel 的开源 Agent 框架（beta）：核心能力落在约定目录里——`instructions.md`、`tools/`、`skills/`、`channels/`、`schedules/`，项目可检视、可扩展，偏「可运维的 durable agent」。

**用法**  
[github.com/vercel/eve](https://github.com/vercel/eve) · [eve.dev](https://eve.dev)。`npx eve@latest init my-agent` 脚手架后，在 `agent/tools/` 加 TypeScript 工具，在 `agent/agent.ts` 选模型即可跑通；文档可在 `node_modules/eve/docs` 本地阅读。

**应用场景**  
要做带定时任务/多通道（HTTP、Slack 等）的长期 agent 产品，或希望 agent 配置像普通代码仓库一样 review。

**推荐学习程度**：进阶

---

## 3. PrimeIntellect-ai/prime-agent — RLM + 持续 Harness 的长程编码 Agent

**介绍**  
面向长程编码与研究的开源 agent：用 Recursive Language Model（把上下文当变量、把子 agent 当可编程调用）+ Continual Harness（记忆、skill、子 agent 规格可沉淀并小步改进）。适合「跑很久」而不是单轮问答。

**用法**  
[github.com/PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)。按 README 安装后用 TUI；可用 `/goal`、`/autonomous`、心跳与调度做跨会话目标与预算内自治。重点读 RLM 与 harness 状态如何落盘。

**应用场景**  
多小时评测/研究流水线、需要跨终端重连的编码任务、想研究「持久状态如何反哺 agent」的人。

**推荐学习程度**：深度

---

## 4. lsdefine/GenericAgent — ~3K 行自进化电脑控制 Agent

**介绍**  
极简自进化自主 agent：核心约 3K 行，用少量原子工具 + 短 Agent Loop，让 LLM 控制浏览器、终端、文件系统、键鼠与屏幕视觉（还可 ADB）。强调本地优先与 skill 树成长。

**用法**  
[github.com/lsdefine/GenericAgent](https://github.com/lsdefine/GenericAgent)。克隆后按 README 配置模型和权限，`python launch.pyw` 或桌面端启动；先跑短任务观察工具调用与记忆，再试 Goal mode 做限时自驱优化。

**应用场景**  
想读懂「最小可用电脑控制 agent」、做桌面/浏览器自动化、或研究 skill 库如何从短种子长出来。

**推荐学习程度**：进阶

---

## 5. JuliusBrussee/caveman — 用「少说话」砍 Agent Token

**介绍**  
面向 coding agent 的 skill + 代理：逼输出变短（caveman 风格），在保持代码准确的前提下显著降 token；已被研究引用，也适合当作「输出压缩」实验对象，而不只是玩笑。

**用法**  
[github.com/JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman)。按仓库说明装到 Claude Code 等环境后，用 `/caveman`、`/caveman-review`、`/caveman-commit` 等命令；可对照 `/caveman-stats` 看本会话真实省了多少。

**应用场景**  
长会话上下文吃紧、想压低 coding agent 账单、或研究「风格约束如何影响工具调用成本」。

**推荐学习程度**：入门
